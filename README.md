# Unitree G1 Arms MVP

## Актуальный сценарий: коробка двумя руками

Снимок проекта для Unitree G1 EDU от 25 августа 2026 года. Основной запуск:
`run_box_detect_and_plan_fixed_dds.sh`. Система обнаруживает коробку через
RealSense и сервер YOLO, рассчитывает подход рук с проверкой препятствий,
формирует двуручное сжатие `flat-squeeze` и удерживает коробку. Подъём коробки
в этом сценарии не выполняется; ходьба задаётся отдельно от программы рук.

Для запуска на роботе необходимы Unitree SDK2, камера RealSense, доступный
сервер детекции и корректная калибровка. Адрес сервера задаётся через
`SERVER_URL`. По умолчанию скрипт работает в режиме планирования;
реальное движение включается параметром `EXECUTE=1` только после проверки
конфигурации на конкретном роботе.

Размеры коробки в сохранённых параметрах запуска: 28 × 16 × 20 см. В
эксперименте использовалась коробка 30 × 15 × 20 см; при воспроизведении
установите `BOX_WIDTH`, `BOX_HEIGHT` и `BOX_DEPTH` по фактической ориентации
коробки. Описание алгоритма находится в `BOX_TWO_HAND_CODE_GUIDE.md`.

Ниже сохранена документация ранних задач проекта; она относится к другим
сценариям управления руками.
Код для первых трех задач:

1. Свободное параметрическое управление рукой и трехпалой кистью.
2. Доведение до известного объекта, захват и подъем.

Проект специально сделан безопасным: по умолчанию команды работают в `--dry-run` и только печатают, что было бы отправлено роботу.

## Координаты

Во всех командах используется система координат `base_link`:

- `x` - вперед от корпуса робота, метры.
- `y` - влево/вправо от центра робота, метры.
- `z` - высота, метры.

Пределы безопасности лежат в `arms/safety.py`. Их нужно откалибровать на реальном роботе.

## Задача 1

Ручное движение руки в точку и открытие/закрытие кисти:

```bash
python -m arms.task1_parametric_control --hand right --x 0.35 --y -0.18 --z 0.75 --grip open --dry-run
python -m arms.task1_parametric_control --hand right --x 0.35 --y -0.18 --z 0.75 --grip close --dry-run
```

Для отправки на UDP-контроллер руки:

```bash
python -m arms.task1_parametric_control --hand right --x 0.35 --y -0.18 --z 0.75 --grip close --arm-host 127.0.0.1 --arm-port 15001
```

## Задача 2

Подведение к известному объекту, захват, подъем и удержание:

```bash
python -m arms.task2_pick_lift --hand right --object-x 0.38 --object-y -0.16 --object-z 0.72 --grasp wrap --dry-run
```

Сценарий делает:

1. Подход над объектом.
2. Опускание к объекту.
3. Закрытие трехпалой кисти выбранным хватом.
4. Подъем.
5. Удержание 5 секунд.

## Что уже готово

- CLI для задач 1, 2 и 3.
- Проверка безопасной зоны.
- UDP-клиент для движения руки в стиле `g1_arm_keyframe_player`.
- Абстракция трехпалой кисти Dex3.
- Три пресета хвата Dex3: pinch, wrap, side.
- Dry-run backend, чтобы тестировать без робота.

## Что нужно подключить на роботе

В `arms/dex3_hand.py` есть класс `UnitreeDex3Backend`. В него нужно вставить реальные вызовы Unitree SDK для Dex3-1, когда на роботе будет известен точный Python/C++ API.

В `arms/arm_client.py` сейчас отправляется JSON:

```json
{
  "action": "move_xyz",
  "hand": "right",
  "target": {"x_m": 0.35, "y_m": -0.18, "z_m": 0.75},
  "seq": 123
}
```

Если текущий `g1_arm_keyframe_player` принимает только именованные действия (`open`, `home`), его нужно расширить приемом `move_xyz`.
